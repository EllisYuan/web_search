先问报告要证明什么

报告类型主要证据组合需要避免的误判
技术事实与故障调查规范、源码、release record，加直接行为观测与反例。文档写“支持”就等于目标环境验证通过。
选型与对比各候选官方依据、同条件实验、独立复现与失败样本。把不同硬件、不同 corpus 的数字合成赢家。
时事与政策原始记录、适用地区与生效版本、独立核实、争议材料。多个转载域名就是多个独立来源。
学术证据综述检索边界、原始研究与适当综合、纳入排除理由、偏差和反证。论文数量等于证据充分；Google-only 足以保证穷尽检索。

这是适用框架的建议，不是跨领域统一评分表。Cochrane、PRISMA-S 和 GRADE 的医疗研究语境不能未经验证就变成所有报告的硬规则。

Search 的具体方向

  1. 由 caller agent 拆解关键问题与子问题，记录版本、时间、地区和所需证据角色。
  2. 通过显式的 SearXNG / Google route 执行有界 Search Batch；按 query 保留结果、可观测状态和失败。
  3. 根据 SERP 选择值得读的候选，独立调用 web_read，不把 snippet 当作正文证据。
  4. 针对未覆盖的问题、同源重复、时效差异和反证缺口追加 query。
  5. 由 caller 决定停止，并明确残余缺口；“没找到”不等于“没有”。

一个 Google engine 并不因经由 SearXNG 就自动变成多引擎覆盖。score、域名数与分页数量都不能证明可信度或全网 Recall。

Web Read 的核心：可复核的目标读取

建议保留原始 capture、版本化 extraction representation、带 locator 的结构化正文，以及受预算约束的 Markdown view。agent 可以先读 metadata、目录和有限正文，再定位 section、关键词或 page，最后补齐解释目标证据所需的上下文。

遇到的内容不能只返回应一起保留或明确缺失
表格里的一个数值裸数字表头、单位、行标签、caption、notes 与位置。
扫描 PDF 的一段 OCR看似确定的纯文本page/image locator、识别来源、未处理区域和不确定性。
长文中的结论孤立句子heading、已识别的脚注和相关段落；未知的语义关联不得假称完备。
继续读取重新抓取 URL 后接上旧 offset固定内容版本、明确的 continuation 范围及失效状态。

抽取尚未完成、只处理部分 page、本次输出达到上限，是不同情况。尤其对于长扫描件，继续处理下一页与读取已生成内容需要不同的状态语义。

支持范围不再为实现方便缩水

静态 HTML、JavaScript 页面、text／mixed／scanned PDF、网页文字图片和独立图片 URL 的 OCR 均保留在首版范围内，继续满足免费开源、Windows、CPU-only 的约束。

已有 Web Read prototype resolution 支持功能路径可继续。后续优先沿用其可运行 baseline 做有针对性的比较，不凭另一库的功能列表推翻已有证据。支持格式也不意味着可以保证任意复杂页面无损；失败必须显式披露，但不能以永久返回 unsupported 代替必需格式的实现。

如何验证它真的更好

冻结同一批 Source 与 extraction 结果，用同一 agent/model 和可比预算，对比 bounded full Markdown、固定分段、结构化分段，以及定位后扩展的 evidence window。披露策略的比较不能偷换更好的 OCR 或额外来源。

首先检查关键证据覆盖、quote fidelity、限定条件是否保留和错误恢复，再比较 token、工具调用次数、首次有用证据时间与资源成本。少输出但漏掉脚注，不算改进。

尚无直接证据证明本项目的具体交互方案已经最优。研究提出的是可检验的设计，不是已完成的效果证明。

核心一手依据

  • Cochrane Handbook · Searching and selecting studies：检索范围与来源组合；有领域适用限制。
  • PRISMA-S：可复核的检索报告，不是可信度评分。
  • SearXNG Search API：参数、instance 与 engine 的能力边界。
  • W3C Web Annotation：quote、position 与 source state 的定位基础。
  • Lost in the Middle 与 SWE-agent：上下文位置与工具反馈设计的间接实证，不是本项目 A/B。
  • CommonMark 与 GFM：Markdown 表达能力及复杂结构限制。
